\section{The tool and what you need}

\code{flagmatic_to_lean.py}\, converts a \textbf{Flagmatic certificate (JSON)} into a
\textbf{Lean proof file (\code{.lean})}. The certificate holds only \emph{numeric
data} --- matrices and a list of flags --- and this tool maps those numbers to Lean
identifiers and attaches the positive-semidefiniteness lemmas, density tables, and
product expansions automatically. So a single final \code{lake build} turns it into a
\textbf{theorem verified in the kernel} (when all the data is in place, even the proof
body is filled in automatically).

\medskip\noindent You need three things to start.

\begin{itemize}
  \item \textbf{Python 3} --- runs the converter (standard library only, nothing to
        install). \code{pip install networkx} is needed only when you have to enumerate
        a graph list of a \emph{new size}.
  \item \textbf{A working Lean / \code{lake} setup and this repository} --- where the
        generated \code{.lean} is actually built and verified. The canonical
        flag/graph definitions and the forbid-graph library all live in this repo too.
  \item \textbf{One certificate JSON} --- the input to convert; it encodes \emph{which
        density inequality to prove under which forbid}. Ready-to-use examples are in
        \code{LeanFlagAlgebras/Flagmatic/Certificates/}.
\end{itemize}

\noindent\textbf{All commands below are run from the repository root.}

\section{The workflow, step by step}

You normally use \code{flagmatic_to_lean.py}'s subcommands in the order \code{inspect}
$\to$ \code{check-deps} $\to$ \code{gen-skeleton}, then verify with \code{lake build}.
Since \code{check-deps} prints, for each missing item, the exact command to run on its
\code{fix:} line, the rule is simply:

\begin{quote}
\textbf{Run the \code{fix:} actions top to bottom and re-run \code{check-deps} until
everything is \code{[OK]} $\;\to\;$ \code{gen-skeleton} $\;\to\;$ \code{lake build}.}
\end{quote}

\noindent The steps below use Mantel (forbid $K_3$, edge density $\le 1/2$) as the
worked example.

\subsection*{Step 1 --- \texttt{inspect}: check parsing and the forbid status}

\begin{lstlisting}[language=shell]
python LeanFlagAlgebras/Flagmatic/flagmatic_to_lean.py inspect LeanFlagAlgebras/Flagmatic/Certificates/mantel_cert.json
\end{lstlisting}

\noindent If every \code{->} resolves without error, you're fine. The
\code{forbid graph:} line shows the forbidden graph's canonical index and whether it is
defined in Lean (the \code{idx} you need to define a complete graph by hand is right
here). The \code{required JSON files} block at the bottom lists every file this
certificate needs.

\begin{lstlisting}[style=output]
=== mantel_cert.json ===
description: 2-graph; maximize 2:12 density; forbid 3:121323
bound: 1/2
forbid graph: 3:121323  ->  Flag_3_0_0_3   [defined in CommonGraphs.lean (tag K3)]

admissible graphs (host-size):
                  '3:'  ->  FlagAlgebra_3_0_0_0     density=0
                '3:12'  ->  FlagAlgebra_3_0_0_1     density='1/3'
              '3:1213'  ->  FlagAlgebra_3_0_0_2     density='2/3'

types:
        '1:'  ->  FlagType_1_0

sigma-flags per type:
  type 0 ('1:'):
                 '2:(1)'  ->  FlagAlgebra_2_1_0_0
               '2:12(1)'  ->  FlagAlgebra_2_1_0_1

required JSON files:
  graphs: ['graphs_3.json', 'graphs_1.json']
  flags: ['flags_2_1_0.json']
  forbid_indices: ['graphs_3_K3_free_indices.json']
  density_loaders: ['density_3_1_0_from_2_1_0_forbid_K3.json']
\end{lstlisting}

\noindent\textbf{If you get stuck:} \code{no graph in graphs_N.json isomorphic ...} or
\code{FileNotFoundError} means the canonical graph/flag list for that size is missing.
Build the file for the size named in the error as shown below, then re-run
\code{inspect} --- \textbf{the graphs (\code{graphs_<n>}) first, then the flags
(\code{flags_<n>_<k>_<t>}) on top of them}.

\begin{lstlisting}[language=shell]
# 1) graphs_<n>.json : open generate_graphs.py, in its __main__ last line change
#    generate_graphs_json(0) -> generate_graphs_json(<n>), then run:
python LeanFlagAlgebras/Flags/generate_graphs.py
# 2) flags_<n>_<k>_<t>.json : needs graphs_<n> and graphs_<k> to exist first
python LeanFlagAlgebras/Flags/generate_flags.py <n> <k> <t>
\end{lstlisting}

\noindent You don't have to work out which sizes you need in advance --- just make
whatever the error points to; Step 2's \code{check-deps} also pinpoints any missing file.

\subsection*{Step 2 --- \texttt{check-deps}: check everything is in place}

\begin{lstlisting}[language=shell]
python LeanFlagAlgebras/Flagmatic/flagmatic_to_lean.py check-deps LeanFlagAlgebras/Flagmatic/Certificates/mantel_cert.json
\end{lstlisting}

\noindent If every line is \code{[OK]} (exit code 0), go straight to Step 3. The check
also covers whether the forbid graph is defined and whether \code{FlagDef.lean} actually
loads the flags you need:

\begin{lstlisting}[style=output]
Dependency check for: 2-graph; maximize 2:12 density; forbid 3:121323
  [OK     ] LeanFlagAlgebras/Flags/Graphs/graphs_3.json
  [OK     ] LeanFlagAlgebras/Forbid/CommonGraphs.lean
          purpose: forbid graph '3:121323' is defined in CommonGraphs.lean (tag K3)
  [OK     ] LeanFlagAlgebras/Flags/Densities/graphs_3_K3_free_indices.json
  [OK     ] LeanFlagAlgebras/Flags/Graphs/graphs_1.json
  [OK     ] LeanFlagAlgebras/Flags/Flags/flags_2_1_0.json
  [OK     ] LeanFlagAlgebras/Flags/Densities/density_3_1_0_from_2_1_0_forbid_K3.json
  [OK     ] LeanFlagAlgebras/Flags/FlagDef.lean
          purpose: FlagDef.lean must load empty-typed 3-vertex flags (FlagAlgebra_3_0_0_*)
  [OK     ] LeanFlagAlgebras/Flags/FlagDef.lean
          purpose: FlagDef.lean must load typed flags FlagAlgebra_2_1_0_*
  [OK     ] LeanFlagAlgebras/Flags/FlagDef.lean
          purpose: FlagDef.lean must load typed flags FlagAlgebra_3_1_0_*
\end{lstlisting}

\noindent When you see \code{[MISSING]}, that line's \code{fix:} is the exact command
(or one-line addition) that resolves it. Run the \code{fix:} actions top to bottom and
re-run \code{check-deps}, repeating until everything is \code{[OK]}. A missing item is
always one of two kinds --- a \textbf{data JSON file that isn't on disk}, or a
\textbf{definition/load missing on the Lean side}.

For example, if you use a forbid graph $C_4$ that isn't defined yet, \code{check-deps}
tells you to define that graph first:

\begin{lstlisting}[style=output]
  [MISSING] LeanFlagAlgebras/Forbid/CommonGraphs.lean
          purpose: forbid graph '4:12233441' must be defined in CommonGraphs.lean
          fix:     define `def C4 ...` + `C4_toFinFlag_eq` by hand (see below)
  [MISSING] ...Densities/graphs_4_???_free_indices.json
          purpose: forbid-free index list (define the forbid graph first to pin the tag)
\end{lstlisting}

\medskip\noindent\textbf{(1) Define the forbid graph (\code{CommonGraphs.lean}).}
A \emph{complete graph} $K_r$ needs a single line, \code{generate_complete_graph r idx}
(read \code{idx} off the \code{forbid graph:} line from \code{inspect} in Step 1). Any
other graph (e.g.\ $C_4$) needs a hand-written \code{def} and \code{_toFinFlag_eq} ---
copy the verified $C_4$ example in the same file, using the \emph{canonical labeling}:

\begin{lstlisting}[style=output]
def C4 : SimpleGraph (Fin 4) := {
  Adj i j := match i, j with
    | 0,1 | 1,0 | 0,2 | 2,0 | 1,3 | 3,1 | 2,3 | 3,2 => true
    | _,_ => false }

lemma C4_toFinFlag_eq : C4.toFinFlag = ⟨4, Flag_4_0_0_8⟩ := by
  simp [toFinFlag, C4]; congr
  all_goals { ext i j; fin_cases i <;> fin_cases j <;> simp [Sym2Graph_4_0_0_8, mkEdgeFinset] }
\end{lstlisting}

\noindent The edge set must match the canonical graph exactly (a different labeling
makes the short proof above fail). Find the edges with \code{#print Sym2Graph_4_0_0_8}
(or \code{Sym2LabeledGraph_...} for a typed graph) and copy them straight into
\code{Adj}.

\noindent The name you give the definition (\code{C4}, \code{K6}, ...) is the
\textbf{tag}. The data-file names and the converter's forbid detection both key off this
tag, so once the definition is in place and you re-run \code{check-deps}, the data-file
\code{fix:} lines become concrete commands.

\medskip\noindent\textbf{(2) Data JSON.} The forbid-free index file and the
density-coefficient file. Just run the \code{gen_free_indices.py} /
\code{calculate_densities.py} commands from \code{fix:} (the file names, \code{--host},
and \code{--tag} are all filled in); if a flag file the density step reads is missing, a
\code{generate_flags.py} command is prepended, so run them in order.

\medskip\noindent\textbf{(3) FlagDef loads (\code{FlagDef.lean}).} Even when the JSON
exists, the build breaks if those flags aren't \emph{instantiated} on the Lean side.
\code{fix:} gives the one line to add (\code{generate_empty_typed_flags <n>} or
\code{generate_flags <k> <typeNum> <n>}). Adding it rebuilds \code{FlagDef} (large
\code{n} is slow), so add only the sizes you actually need.

\medskip\noindent Once each \code{fix:} is done and \code{check-deps} comes back all
\code{[OK]}, move on to Step 3.

\subsection*{Step 3 --- \texttt{gen-skeleton}: generate the Lean proof file}

\begin{lstlisting}[language=shell]
python LeanFlagAlgebras/Flagmatic/flagmatic_to_lean.py gen-skeleton LeanFlagAlgebras/Flagmatic/Certificates/mantel_cert.json LeanFlagAlgebras/Flagmatic/Mantel.lean --namespace Mantel --force
\end{lstlisting}

\noindent This one line means success. The file contains the imports, \code{load_*}
commands, the matrices and PSD lemmas, the flag vectors, and the \textbf{automatically
proved main theorem}.

\begin{lstlisting}[style=output]
wrote 5757 chars to ...\Mantel.lean (namespace Mantel)
\end{lstlisting}

\noindent(\code{--force} overwrites an existing file of the same name; omit
\code{--namespace} to derive it from the target file name.)

\noindent If Step 2 passed all \code{[OK]}, the main theorem is filled in too --- no
\code{sorry} is left. (Only for the rare certificate shapes the converter doesn't yet
handle --- e.g.\ a block whose number of flags is outside the supported range --- is the
proof body left as a \code{sorry} stub.)

\subsection*{Step 4 --- \texttt{lake build}: verify in the kernel}

\begin{lstlisting}[language=shell]
lake build LeanFlagAlgebras.Flagmatic.Mantel
\end{lstlisting}

\noindent If it finishes without errors, \textbf{the proof is verified in the Lean
kernel}. The result is \code{theorem mantel_flagAlgebra} inside the \code{Mantel.lean}
you just generated.

\noindent\textbf{If the build is very slow or runs out of memory:} that is almost always
the large \code{native_decide} / kernel-checking steps, not a timeout (the generated file
already sets \code{maxHeartbeats 0}). Build just this one module (as above), close other
heavy processes, and retry.

\medskip\noindent We used Mantel as the example throughout. \textbf{Any other certificate
works the same way} --- in the commands above, change only the certificate path and the
target \code{.lean} file name / namespace, and follow Steps 1--4 unchanged.
