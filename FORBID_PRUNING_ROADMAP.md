## Goal

Make the **genuine-pruning** forbid-free pipeline work for an **arbitrary forbidden graph
F** (eventually a finite *family* of forbidden graphs), end to end:

1. The user defines F in a prescribed format, with convenience commands for common graphs
   (complete graphs, cycles, paths, …).
2. The flags are generated by **genuine pruning** — F-containing graphs are never carried
   forward — rather than by enumerate-all-then-filter.
3. This is justified by the bridge **F-free ↔ density = 0**, connecting the combinatorial
   pruning predicate to the analytic forbid framework.
4. The forbid-free generation/expansion commands run on this pruning-based core.

## Decisions (locked)

- **D1 — Induced semantics.** "F-free" = *no induced copy of F*, which is exactly
  `flagDensity₁ F (unlabel G) = 0`. For complete graphs (K_r) this coincides with the usual
  (non-induced) notion. **Non-induced forbidding of non-complete graphs is out of scope**
  for now (its RHS would not be `density₁ = 0`).
- **D2 — Forbidden graph as a computable graph.** Represent F as a `Sym2Graph m` and read
  its edges directly. This decouples the framework from the *canonical forbidden flag*
  (`Sym2Flag_r_0_0_idx`) and from the empty-typed enumeration, so a forbid no longer needs
  `generate_empty_typed_flags r` + a `_toFinFlag_eq` index lookup. (This is also what frees
  `MantelHfree` from its irreducible flag-setup.)
- **D3 — Keep multiple forbidden graphs in mind.** Build the pruned generator and its
  completeness **generic in the H-free predicate** `p : ∀ {n}, Sym2Graph n → Prop`
  (decidable, iso-invariant, monotone under vertex deletion). The single-graph case is
  `p G := ¬ inducedContains F G`; the family case is `p G := ∀ F ∈ Fs, ¬ inducedContains F G`.
  See "Multi-graph design notes" below. Do **not** hardcode a single F into the generator.

## Current state (baseline, as of creation)

- **Filter-based forbid-free framework — general, wired.** `ForbidFreeGenerator.lean`
  (`generate_forbid_free_empty_typed_flags`, `generate_forbid_free_flags`) enumerates *all*
  graphs (`genSym2GraphsDedup n`) and filters by H-freeness. Works for any forbid (K3/K4/K5
  used). Completeness `genFlagsHfree_toFinset_eq` is **already generic in the graph
  predicate `q`** — reuse this.
- **Genuine pruning — K3-only, NOT wired.** `Flags/ForbidFreePruned.lean`: `hasTri`,
  `augmentAllTriFree`, `augRepsTriFree`, `hasTri_of_eqv`, `hasTri_of_restrict`,
  `augRepsTriFree_complete` (all sorry-free). Triangle-specific. Validated to K3-free class
  counts (7/14/38 at n=4/5/6). ~1.8× faster at the graph level than the filter.
- **The bridge is unproven.** `triFree G ↔ flagDensity₁ K3.toFinFlag.2 (unlabel ⟦G⟧) = 0`
  exists only as prose in `ForbidFreePruned.lean` and `papers/Notes/forbid_free_pruning_work.md`.
- **Forbid resolution today.** `resolveForbidGraph` (DensityThmGenerator) finds `K{r}` +
  `K{r}_toFinFlag_eq` and reads the canonical forbidden flag from it; `isHfree` uses
  `sym2EmptyTypeFlagDensity₁ Sym2Flag_r_0_0_idx`. Both depend on the forbidden flag (D2 removes this).
- **Existing general containment (meta only).** `containsForbiddenSubgraph` (DensityThmGenerator)
  is an elaboration-time `Bool` on edge lists and is **non-induced**; not a Lean-level Prop on
  `Sym2Graph`. We need an induced Lean Prop (the general analogue of `hasTri`).

## Multi-graph design notes (for D3)

- **Predicate.** Family H-free = `fun G => ∀ F ∈ Fs, ¬ inducedContains F G`. Iso-invariant and
  restrict-monotone because a finite `∀`/`∃` of iso-invariant/monotone predicates is.
- **Generic pruned generator.** Parameterize by the predicate (not by F), exactly as
  `genFlagsHfree_toFinset_eq` is parameterized by `q`. Single F and families are instances.
- **Bridge.** Conjunction of per-F bridges; or use `∑_{F ∈ Fs} flagDensity₁ F G = 0` (densities
  are ≥ 0, so the sum is 0 iff each is 0) if a single scalar predicate is more convenient
  downstream.
- **Representation.** Allow `Fs : List (Σ m, Sym2Graph m)` (graphs of possibly different sizes).
- **Pitfall.** A family at *different* sizes means the per-F density lemmas have different flag
  sizes — keep the generator's predicate purely combinatorial (on `Sym2Graph`), and only invoke
  the bridge at the wiring layer.
